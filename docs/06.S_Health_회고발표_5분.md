## 1장 — PCTF · 작업시나리오 · Cursor 사용

**PCTF**

| 구분 | 설명 |
|------|------|
| **P** | AI 역할 (시니어 Java, QA, 발표자 등) |
| **C** | 프로젝트·docs·선행 단계·제약 |
| **T** | 수행 작업 순서·범위 |
| **F** | 산출물 경로·검증 (mvn test 등) |

**작업시나리오 흐름**

0 rules → 1 스멜 → 2 1차리팩 → 3 UnitTest → 3-2 DEF/REC → 4 SRP/API → 4-2 2차리팩 → 5 결함체계 → 6 회고

**Cursor 사용**

- `N단계_PCTF.md` 복사용 블록 또는 `@` 첨부
- 공통: `@작업시나리오` `@README` `@.cursorrules` `@SHealthRequirements.txt`
- 이전 단계 `docs/`·`Report/` 함께 첨부

## 3장 — 단계 의존 · 구분 · 실습 성과

**의존 관계**

`0→1→2→3→3-2→4→4-2→5→6` · 3 Green 후 3-2 · 4-2 후 5(문서만) · 6 회고(코드 수정 없음)

**3-2 vs 5단계**

| | 3-2 | 5 |
|---|-----|---|
| 질문 | 무엇이 잘못·부족한가 | 어떻게 관리·보고·측정할 것인가 |
| 산출 | DEF/REC 레지스터 | 분류·템플릿·메트릭 |

**실습 성과**

- 구조: God Class 1개 → 12클래스 + 파사드
- TC: 1건 → **40건 Green** (QM-01 100%)
- DEF: Resolved 4 / Test-Locked 1 / Open 1
- AI 코드 리뷰: **4/5**

**Takeaway**

1. PCTF + `@docs/` + `@작업프롬프트/` = 단계별 재현 가능  
2. 테스트(3) → 리팩토링(4·4-2) 안전망  
3. 결함: 통합(3-2) → 체계화(5) → 회고(6)
