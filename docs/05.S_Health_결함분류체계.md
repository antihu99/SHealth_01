## 2. 분류 축 정의

| 코드 | 이름 | 정의 | SHealth 예시 |

| **SPEC** | Spec-Gap | 명세와 구현 불일치·명세 미정 | DEF-02 빈 나이대, DEF-04 height=0 |


## 5. 3-2단계 ID·상태와의 정합 규칙

1. **DEF-xx ID는 변경하지 않는다.** 5단계는 분류 축·상태만 보강한다.
2. **Test-Locked → Resolved** 전환 시 반드시 TC 갱신·`mvn test` Green을 증거로 남긴다.
3. **REC-xx**는 결함이 아니라 **조치 권고**; Type=DEBT/TEST 등으로만 REC를 분류 표에 넣지 않는다.
4. **명세-구현 갭**은 Type=SPEC 또는 FUNC 중 **구현이 명확히 틀린 경우 FUNC**, 명세 미정·정책 선택은 SPEC.
5. 4단계 이후 신규 결함 발견 시 DEF-07부터 추가하고, 본 문서 §4 표에 행을 추가한다.

## 6. 결함 vs 권장사항(REC) 구분

| 구분 | DEF (결함) | REC (권장) |
|------|------------|------------|
| 정의 | 현재 **잘못·부족·갭**인 동작·구조 | **개선하면 좋은** 조치 |
| ID | DEF-xx | REC-xx, REC-Rxx(완료) |
| 상태 | §2.4 | [ ] 완료 체크 |
| 예 | DEF-01 BMI=25 | REC-01 «DEF-01 수정» |
| 동일 이슈 | 현상=DEF, 조치=REC | 중복 서술 지양 |
